# Introducing PDFjet

PDFjet is a library for creating PDF documents from programs. It draws text in any script, tables that break across pages, charts, barcodes and images, and it writes documents that are accessible to screen readers and fit for long-term archiving when you ask it to.

It began in 2000, when there were few PDF libraries and none that was small, fast and written in plain Java. The name says what it has been about ever since: a jet is fast and lean. PDFjet writes a 500-page document with an embedded font in under a tenth of a second, and it writes each page out and frees it as soon as the next one starts, so a long document does not need more memory than a short one.

PDFjet comes in four languages, Java, C#, Go and Swift, with the same API and the same output. Each port is written in its own language, with no native code and no dependencies: the Java library is one jar of less than half a megabyte. The four ports are checked against each other on every change: every example is built in the four languages, and the PDFs they write must draw the same text in the same fonts, sizes and positions, page by page.

## What is in the library

- Text in Latin, Greek, Cyrillic, Chinese, Japanese, Korean, Thai, Hebrew, Arabic and Persian, with right to left text, kerning and fallback fonts.
- 272 font files ready to use, from the IBM Plex, Noto, Source Serif and JetBrains Mono families, and any OpenType or TrueType file on the computer.
- Text lines, text blocks, columns and frames that wrap and flow text, and tables that break across pages and repeat their header rows.
- Bar charts, donut charts, XY charts and calendars.
- Barcodes: Code 128, Code 39, UPC-A, EAN-13, QR codes, Data Matrix and PDF417.
- PNG, JPEG and BMP images, and SVG drawn as vector graphics.
- Links, bookmarks, annotations, attached files, layers and forms.
- PDF/UA for accessibility, and PDF/A-1, 2 and 3 for archiving, each with one setting.
- AES-256 encryption with passwords and permissions.
- Reading existing PDFs: merging, splitting and adding to their pages.

## How this booklet is organized

The first chapters show how to install PDFjet, what a PDFjet program looks like, and how to use the library efficiently. The chapters after them go through all 51 examples that come with PDFjet, grouped by topic. Each example starts with what it shows and what to look for, followed by its complete source code, exactly as it is in the repository, where the examples are built and their PDFs checked on every change.

To see what an example draws, run it: every example writes a PDF named after it, such as Example_24.pdf. The examples read their fonts, images and data from the fonts, images and data folders of the repository, so run them from its root folder.

# Getting started

## Installing PDFjet

@lang java
Build PDFjet.jar with ./build-java.sh from the root of the repository, which also builds and runs the examples, and put the jar on the class path of your program. PDFjet runs on Java 8 and later.
@end
@lang csharp
Build bin/release/net8.0/PDFjet.dll with ./build-dotnet.sh from the root of the repository, which also builds and runs the examples, and add a reference to it in your project. PDFjet runs on .NET 8 and later.
@end
@lang go
Add the module to your program with the go command. The module path carries the major version, as Go requires from version 2 on.

    go get github.com/edragoev1/pdfjet/v9@latest

The Go module has the source of the library and the examples only. Copy the fonts folder of the repository next to your program; the core fonts need no files.
@end
@lang swift
Add PDFjet to the Package.swift of your package, and the PDFjet product to the target that uses it:

    dependencies: [
        .package(url: "https://github.com/edragoev1/pdfjet.git", from: "9.0.0"),
    ],
    targets: [
        .executableTarget(name: "App", dependencies: [
            .product(name: "PDFjet", package: "pdfjet"),
        ]),
    ]
@end

The fonts that come with PDFjet, such as IBMPlexSans.Regular, are paths relative to the working folder, so a program that uses them runs in a folder that has the fonts folder of the repository.

## Hello, World

This program writes hello.pdf with one line of text in English, Greek and Bulgarian, in IBM Plex Sans at 18 points.

@code java
import com.pdfjet.*;
import com.pdfjet.fonts.*;
import java.io.*;

public class Hello {
    public static void main(String[] args) throws Exception {
        PDF pdf = new PDF(new BufferedOutputStream(new FileOutputStream("hello.pdf")));
        Font font = new Font(pdf, IBMPlexSans.Regular).setSize(18f);
        Page page = new Page(pdf, Letter.PORTRAIT);
        new TextLine(font, "Hello, World! Γειά σου, κόσμε! Здравей, свят!").setLocation(50f, 100f).drawOn(page);
        pdf.complete();
    }
}
@end

## The shape of a PDFjet program

Every PDFjet program has the same four steps. It creates a PDF on an output stream, adds the fonts and images it needs to the PDF, creates pages, and draws on each page. When it is done, it completes the PDF, which writes what is left and closes the stream.

Positions are in points, 72 to an inch, from the top left corner of the page, with y growing down the page, as a page is read. Every component, a text line, a text block, a table, an image, a chart or a barcode, has a location that setLocation sets, and a drawOn method that draws it on a page. drawOn returns the x and y of the bottom right corner of what it drew, so the next component can start below it.

A font can be one of the fonts that come with PDFjet, such as IBMPlexSans.Regular, any OpenType or TrueType file, or one of the 14 core fonts, such as Helvetica, which every PDF viewer has and which is not embedded. The embedded fonts draw any character they have, and are the ones to use for accessible and archival documents. The core fonts make the smallest documents, but draw only the characters of Windows Latin 1.

For an accessible document, set the compliance to PDF/UA-1 and give the document a title, before anything else. PDFjet then tags every text line, text block, table cell and image, and marks lines, shapes and backgrounds as decoration, which screen readers skip. For an archival document, set one of the PDF/A levels instead.

# Working efficiently

PDFjet is fast by design, and a few habits keep it that way.

- Create each font once and use it everywhere. A Font object embeds its font in the PDF once, however many pages use it, and a text line can draw in another size of the same font with setFontSize, without a second font.
- Use the .stream fonts that come with PDFjet, such as IBMPlexSans.Regular. They are the same fonts, compressed once ahead of time, so they load faster than the .otf and .ttf files and are written to the PDF as they are.
- Add an image to the PDF once and draw it on as many pages as you like. The image data is written once.
- Write to a buffered stream, and let PDFjet write each page out as the next one starts. A document of thousands of pages needs no more memory than one page.
- For a table of tens of thousands of rows, use BigTable, which writes the rows as it reads them, rather than Table, which holds every cell until it is drawn. Example 43 writes 124,716 rows of a CSV file this way.
- Measure before you draw. drawOn returns where a component ends, and a text block drawn on no page, with drawOn(null), returns its size without drawing it, so a layout can decide where things go before it draws them.
- Leave the compliance, PDF/UA or PDF/A, on from the start. Tagging costs little, and the document is accessible without a second pass.
