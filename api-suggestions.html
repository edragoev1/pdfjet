Second audit, for the v9.0.0 release

PDFjet API Cleanup

The eighteen suggestions of the first audit are done or parked for 10.0. This second pass read the four ports class by class for code drift, for what is still public by accident, and for names that say the wrong thing. It found three bugs and two dozen places where one port does something the others do not; the bugs, all of the drift and then the four inconsistencies the ports shared were fixed the same day and are listed at the end. What remains is a dozen names worth changing before the release.

Basis: audit-api.py --dump at 533ecc67 (102 lines, 101 public types per port), a method-by-method reading of Page, PDF, the shapes, the text classes, the charts and the annotations in all four ports, and the 50 examples. 14 September 2026

Drift between the ports

Places where a port behaved differently from the other three, in output or in how it failed. None changed the 50 examples, which is why the check did not catch them. All seventeen were fixed on 14 September; the list is under Fixed. Three points stay as the README documents them for Go, which cannot overload: Page.AddBDC takes the language, NewParagraph() takes no text line, and Cell.SetBorderColorRGB takes an array, so a border colour once set stays, as Rect and TextBlock do.

Inconsistencies shared by all four ports

These are the same in every port, so they are design choices rather than drift, but two rules for one setting is one too many. The four for 9.0.0, the accessibility text defaults, Color.transparent in the text setters, the fallback font of setFont and Chart against BarChart, were fixed on 14 September and are listed under Fixed; the two below wait for the TextColumn fold.

TextColumn.getHeight and getSize 10.0

Finding

TextColumn.getHeight returns the height that was set, where TextBlock.getHeight returns the height as drawn; the drawn height of a column comes from getSize, which returns a Dimension, a class that exists for this one method.

Suggestion

Part of the TextColumn into TextFrame fold below.

Getters that only TextLine has 10.0

Finding

TextLine has a getter for every setting. TextBlock lacks getters for line spacing, language, right to left, URI and highlight colors; TextColumn lacks them for line spacing, paragraph spacing and the line between paragraphs.

Suggestion

Add them when the text classes are next touched.

Names

The names that still say the wrong thing, or say one thing two ways. The fields that disagreed with their setters were renamed on 14 September and are listed under Fixed.

Abbreviations 9.0.0

Finding

Chart.setDrawHGridLines, setDrawVGridLines, setHGridLineWidth, setVGridLineWidth, setHGridLineDashPattern and setVGridLineDashPattern are the only abbreviated setters in the library; BarChart spells out setGridLineWidth. Shape.H_DASH and V_DASH are the only abbreviated constants. Go qrcode.ErrorCorrectionLevelL repeats the type name where every other Go constant is package.Name, like alignment.Left.

Suggestion

setDrawHorizontalGridLines and the like, Shape.HORIZONTAL_DASH and VERTICAL_DASH, and a Go errorcorrectionlevel package with L, M, Q and H.

One name, two meanings 9.0.0

Finding

setLocation is the top left corner of every Drawable but the center of a DonutChart. Form.setFormWidth repeats the class name where every other class says setWidth. Path.setClosePath(boolean) reads as a command.

Suggestion

DonutChart.setLocation takes the top left corner of the outer circle, or the class documents its center loudly; Form.setWidth; Path.setClosed.

Odd members 9.0.0

Finding
  • TextLine.getStringWidth(text) measures any text; that is Font.stringWidth, which exists.
  • TextLine.advance(leading) moves the line down and returns the new y; the name does not say it moves anything.
  • TextLine.getDestinationX and getDestinationY are the GoTo destination of the line; nothing in the name says so.
  • Arc.setSweepDegreesCW and setSweepDegreesCCW are two setters for one signed angle, in a library where every other angle is counterclockwise and positive.
  • Page.drawCircle takes a PathOperator while drawEllipse has a fillEllipse twin, and drawRectRoundCorners has neither an operator nor a fill twin.
  • Page.transform(float[]) takes the six values at Android Matrix indices, exposed as MSCALE_X and friends.
  • Table.getRowsRendered says "rendered" where the library says "drawn".
  • Go Font.GetAscentAt, GetDescentAt, GetBodyHeightAt and StringWidthFB use At and FB suffixes where the other Go overloads use a type suffix like RGB; Go XMarkCheckBox reads as a type.
  • The private key generator of Bookmark is next in Java, Next in C#, getNext in Go and goToNext in Swift; FileAttachment.setIconPushpin writes PushPin next to Paperclip.
Suggestion

Remove getStringWidth; moveDown(leading); getGoToDestinationX/Y; one setSweep(degrees), counterclockwise; fillRectRoundCorners or a PathOperator on all three; transform(a, b, c, d, e, f) in PDF order; getRowsDrawn.

Spacing has two names and two meanings 10.0

Finding

TextColumn.setParagraphSpacing is a multiple of the line height; TextFrame.setParagraphGap is points. That is the documented gap-versus-spacing rule, but it is the one place a reader meets both for the same thing. On 14 September setParagraphGap became a true gap, added to the height of the last line so paragraphs never overlap, where it was the distance from baseline to baseline; TextFrame is the class that stays.

Suggestion

Goes away with the fold below.

Permissions take an int in two ports and a type in two Document

Finding

Permissions.grant and setAccess take the UserAccess values as an int in Java and Swift and as a typed flags value in C# and Go, and the port note in the README says so. It is the last place a value has two types across the ports.

Fixed on 14 September

The bugs, the crash-class drift, the rest of the drift and then the inconsistencies the four ports shared were fixed the same day, in the four ports, and are listed here so the page stays a record of what was found.

  • Java BarChart.barColor guards a negative index, so a named series with a color per bar draws its legend swatch; the bar chart tests now name such a series in all four ports.
  • Swift Page(pdf, pageObj) strips the comments before it reads the page size, as the other ports do.
  • Title.drawOn tests the prefix text in Java, C# and Go, as Swift did.
  • BaseAnnotation.rotate skips the vertices of a polygon that has none, in Java, C# and Swift.
  • Swift Image(pdf, path) throws a PDFjetError for a missing file; Image(objects, bytes) passes no alpha channel for a gray or 16-bit image; Image.drawOn no longer rounds its link rectangle.
  • Cell.setBorder in Java and C# masks the value with Border.ALL, so no stray bit reaches the underline and strikeout flags.
  • CompositeTextLine.getLocation returns a copy in Java and C#.
  • Go OptionalContentGroup.Clear allocates a new list, so a slice handed out earlier no longer sees later additions.
  • BigTable aligns a number with the same Table.isNumber test in the four ports, instead of each language's float parser; Go BigTable treats an empty delimiter as one field per line and reads lines longer than 64 KB, as Table does.
  • The font parser OTF and the PNG decoder PNGImage are internal in the four ports, as are the ICC profile bytes of Go and Swift and the Swift PDFobj.dict field. CheckBox.xMark stays public: Example_50 uses it to tick the boxes of an existing form, so it is a feature, not an internal, and the audit had it wrong.
  • The stale white fill color of the Go link annotations in Chart, TextBlock, Image, SVGImage, CheckBox, RadioButton and FileAttachment is gone.
  • Drift between the ports. An empty document property or annotation title or contents writes nothing in Java, C# and Swift, as in Go. Go returns errors where it panicked: NewPDFFile returns (*PDF, error), Complete and AddObjects return error, SetTextRenderingMode returns (*Page, error), and the append functions keep the first writer error for Complete; Page.drawPath and Stamp.drawPath with fewer than two points paint nothing in the four ports, where two threw and two stopped the program. Go has NewPDFReader() for the reading-only PDF(), and the README lists NewPDFFile. C# and Swift warn on standard error. Go GetMinMaxY returns [2]float32 and AddObjects takes the slice; Swift Title.setPrefix and TextLine.advance are @discardableResult, addResourceObjects(from:) is labelled like getPageObjects(from:), and the three addResource forms take the objects as inout; C# setPenColor(int) and setBrushColor(int) call the array overloads, and the saved state stores brush then pen in the four ports. Go has NewEmptyCell(font); a cell keeps its column span, borders, underline and strikeout as fields in the four ports; Table.getWidth of an empty table is 0 everywhere; RadioButton has its own fontSize; Form copies its fields and Go Form.DrawOn names a nil page, while Swift Form unwraps the page like CheckBox and RadioButton. getComponents returns a copy in the four ports, and Font(pdf, coreFont) rejects a number outside the fourteen in Java, C# and Swift (Go's core fonts are typed). Go's rotateAroundCenter lives with Container, the unused annotationType type and the Float.MIN_VALUE comments are gone, the Go doc comments list their parameters the Go way, and DonutChart.java and Slice.java start with the license.
  • Inconsistencies shared by the four ports. Line, Arc, Image, SVGImage, CheckBox, RadioButton and Stamp default altDescription and actualText to none, as Rect, TextLine and the annotations do, where they were a single space: a drawing without a description writes no /Alt and no /ActualText, and its link falls back to its URI. TextBlock.setTextColor and Cell.setTextColor leave the text color unchanged for Color.transparent, as TextLine does, where they made the text white. setFont of TextLine, TextBlock and Cell changes the fallback font with the font unless a different fallback font was set, where TextBlock replaced a fallback that was set and the other two kept the first font as the fallback. Chart follows BarChart: a border width of 0, the default, hides the chart and plot area borders, axis lines of 0.5 run along the left and bottom sides of the plot area, a grid line is drawn at every label, and setSubtitle, setGridLineColor and setAxisLineWidth work as in BarChart. Unit tests cover the four in each port.
  • A field and its setter disagree. The fields are named after their setters in the four ports: BaseAnnotation and Annotation store opacity, which they write as /CA, where the field was transparency; Cell stores borderColor and borderWidth, not strokeColor and strokeWidth; CheckBox stores borderColor and checkmarkColor, not boxColor and checkColor; Form stores strokeWidth, not lineWidth; TextLine stores decorationColor, not lineColor; Chart stores hGridLineDashPattern and vGridLineDashPattern; TextFrame stores paragraphGap, not paragraphLeading; and CompositeTextLine stores superscriptFactor and subscriptFactor. The fields are internal, so no caller changes.

Left for 10.0

Fold TextColumn into TextFrame once its CJK paragraphs, its line between paragraphs and its alignment move over. That also settles getSize, Dimension, the two paragraph spacings and the missing getters above. Touches Example_10, 29, 44, 49 and Cell.setTextColumn.

One table API. Table says setData and drawOn(pdf, pages, pageSize); BigTable says setTableData, setNumberOfColumns, setTextAlignment, complete and getPages. Give them the same names, or make streaming a mode of Table. Touches Example_43 and the seven Table examples.

Stamp keeps its own drawing API by decision: the form XObject is the point, and the API that fills it is a small cost.
